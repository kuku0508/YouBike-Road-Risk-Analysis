# Phase 2：單月原始租借資料唯讀盤點與 schema audit

日期：2026-09-12。範圍：來源索引與2023年11月的完整檔案掃描。沒有清洗、排除、補值、站名合併、OD matrix、graph、SNA、分群、BRouter或事故整合。

**結論：有條件可行。** 原檔具有起訖場站名稱、借還小時、借用日期及獨立時長，可支援以「原始名稱」近似辨識節點與小時尺度的OD設計。但沒有station ID、經緯度或trip ID，無法證明名稱一對一對應實體站點，也不能保證相同六欄必為重複旅次。正式清理前須先處理站點身分與研究範圍的證據缺口。

## 證據與分類

- **Report-specified**：原報告p.7使用借還紀錄建構有向OD，核心為2023–2024；詳見Phase 1文件。
- **Observed in raw data**：本文件的全檔計數、字元、欄寬及時間結果，只描述這份歷史月檔。
- **Reconstruction decision**：本階段選擇2023/11、以位置c1–c6描述無表頭欄位、只產生audit摘要。
- **Assumption／未確認推論**：一列看起來是單筆租借紀錄、站名可作近似標籤；沒有旅次ID或歷史資料字典，無法確認唯一性與發布端篩選方式。整點時間可能經過去識別化處理，但具體捨入／截位方式未知。

計算證據：[audit-evidence.json](audit-evidence.json)；取得紀錄與76個連結HEAD狀態：[source-receipt.json](source-receipt.json)。可重跑程式：[audit_youbike.py](../src/audit_youbike.py)。

## Source index audit

這份使用者稱為「Excel索引表」的檔案實際是CSV，並非XLS/XLSX：**工作表名稱不適用**，不虛構工作表。

- 檔名：`臺北市公共自行車2.0租借紀錄(20260911更新_V5).csv`。
- 大小16,327 bytes；76筆資料列、6欄，有表頭。
- 編碼：全檔可嚴格CP950解碼，UTF-8解碼失敗；這證明相容CP950，不推定原作者使用何軟體儲存。
- 欄位：`發布機關名稱`、`機關代碼`、`UpdateTime`、`SrcUpdateTime`、`fileinfo`、`fileURL`。六欄皆無空白儲存格。
- 年／月沒有分開欄位；由`fileinfo`的日期讀取，僅在audit摘要新增year/month標記，原索引未修改。
- 月份範圍2020/04–2026/07，共76個月份，範圍內無缺月、無重複月份；2023及2024各12月均列出。2026/08之後不在索引範圍，不當作範圍內缺月。
- 所有URL均為同一主機、HTTPS、`.zip`，且年份／月份與`fileinfo`一致；空白或語法不合的URL為0。
- URL樣式：`https://tcgbusfs.blob.core.windows.net/dotapp/youbike_second_ticket_opendata/YYYY/YYYY-MM/YYYYMM_YouBike2.0票證刷卡資料.zip`。
- 2026-09-12以HEAD檢查76個URL，均HTTP 200；只讀標頭，**只有2023/11下載檔案本體**。HEAD成功不證明其餘75個ZIP內容有效或完整。
- 年度分布：2020有9月（4–12）、2021–2025每年12月、2026有7月（1–7）。索引未見年度下載格式／來源主機變更；不能據此宣稱各年ZIP內部schema一致。
- 索引metadata格式差異：75列UpdateTime為ISO 8601，2020/04列為斜線日期格式；更新時間不是旅次時間，也不能保證歷史月檔完整。
- 每月原URL、月份與HEAD結果全部保存在上述JSON，不只保留選中月。

官方[資料集頁面](https://data.gov.tw/dataset/150635)列的主要六欄是索引欄位，不能拿來讀旅次檔。該頁目前另註月份資料有7欄（含車種），與此次2023/11原檔的6欄不同；這是已觀察的metadata／歷史檔不一致，尚不知變更年份。官方頁列授權為政府資料開放授權條款第1版。

## Schema 與 missingness

**沒有原生欄位名稱：首列就是資料，不能讓CSV工具預設吃掉第一筆作表頭。** 2,941,065列全部為6欄，異常欄寬0列。c1–c6是audit位置標記，語意是依官方借還欄位說明及實際值型態判讀，不是補寫原檔表頭；目前官方第6欄「車種」不可套用到這個檔案。

|---|---|---|---|---:|---:|
| c1 | 無 | 借車時間 | datetime字串；整點 | 0 | 0.000000% |

缺失定義為解析後空字串或只有空白字元；沒有把`0`、`?`、`�`或未識別名稱當作缺失。另檢查NULL／NA／N/A／None／NaN／unknown／單獨減號等文字候選，均未出現。欄位前後空白計數均0。

- 起站缺名69列、迄站缺名63列，兩者無重疊：任一端缺名132列（0.004488%）。僅就非空名稱與可解析借車時間而言，2,940,933列具備候選OD欄位；這不等於都已通過站點身分驗證。
- 無station ID、經緯度、行政區欄、trip ID、騎士ID、車輛ID、車種或明示旅次計數欄。
- c1/c3與c6全部可依記錄格式解析；c5全部符合非負時長格式，沒有解析失敗。
- 全六欄字串相同的群組5,059組，共涉及10,160列；超過每組第一筆的列數5,101（0.173441%）。**沒有刪除**。缺trip ID且時間只有整點，無法區分真重送與不同騎乘碰巧同值。

## Station identifier consistency

空白名稱不計入unique station name：借車1,317種、還車2,275種，聯集2,275種。所有非空借車名也出現在還車集合；958種只出現在還車欄，共62,371列還至這些名稱（約2.12%）。這是名稱集合差異，不是「958個已確認市外站」。

- **ID→多name與name→多ID：無法檢查／N/A**，因為兩端均無ID；不是0個衝突。
- 6種名稱含原檔已存在的U+FFFD替代字元`�`，涉及10,457列（0.355551%）；例如`中國醫藥大學附設醫院臺北分�`。嚴格UTF-8成功但原值已有替代字元，故解碼成功不代表文字完整。
- 7種名稱含`?`，涉及14,456列（0.491523%）；例如`糖?文化園區`。疑似字元替換，不能自動猜回正字。
- 17種名稱的半形括號不平衡；可能截斷或命名本身如此，尚未以站表確認。
- 16種名稱含`_數字`結尾，其中14種同時有無後綴的名稱；例如`萬華國中_1`是後綴候選之一。後綴可能代表不同站體、名稱版本或其他編碼，禁止直接移除。
- 只檢查去除前後空白可能形成的碰撞，結果0組；未實施Unicode正規化、同義字或站名修復。
- 還車欄可見`板橋車站`、`新北市政府`等名稱線索；不能假定資料集名稱叫臺北市就代表所有起訖都在臺北市。需要歷史station master及地理證據後才能定義雙端／單端範圍。

字元問題涉及列數可能重疊，不能直接相加當作總壞列。完整問題名稱清單保存在audit evidence；本階段沒有正式station reconciliation。

## Temporal coverage 與 completeness

- c1借車時間：2023-11-01 00:00:00至2023-11-30 23:00:00。
- c3還車時間：相同起訖界線，沒有12月還車紀錄。
- c6日期：2023-11-01至2023-11-30，逐列等於c1的日期；不一致0列。
- 30個借車日期全部存在；30×24=720個借車小時格皆有資料，日期／小時缺口0、借車日期超出11月0列。
- 借還時間的分、秒在全部紀錄均為0；因此時間資訊足夠辨識小時，**不具分鐘／秒級騎乘起訖精度**。原始欄位沒有時區offset，尚不把Asia/Taipei當成已由檔案證實的正式設定。

## Unresolved questions 與 recommended cleaning rules（僅建議）

1. 先找2023/11可對照的歷史站表與欄位字典；對少量`�`、`?`、後綴與只還車名建立證據清單。先不決定正式reconciliation。
2. 釐清來源按借車、還車或兩者日期篩選，以及跨月旅次處理；日期齊全與交易完整性分開報告。
3. 若之後建立清理讀取器，建議明訂此歷史schema為無表頭6欄，另做schema gate；不能把未下載的年份強套為6欄或7欄。
4. 空白站名建議標記待查並在後續分析保留排除理由；本階段不排除。`_1`、`?`、`�`不可自動移除或替換。
5. 完全相同六欄只作duplicate candidate；在沒有唯一鍵或發布端佐證前，不建議直接drop_duplicates。
6. 使用獨立時長作時長檢查候選；零時長／長旅次先檢查，不任意截尾。平假日定義與借／還時歸屬在下一個適當模組明訂。

建議下一個最小任務：**歷史station master來源盤點，加上少量問題站名的唯讀對照可行性檢查**，輸出來源與歧義清單；先不清理全部旅次、不正式合併名稱、不建OD。

## 重跑方式

Python標準函式庫即可，本次在目前工作環境以Python 3.11.0重新驗證；未安裝第三方套件。SQLite暫存庫用來精確比較所有欄位字串，只存於系統暫存目錄並自動移除，須預留約數GB暫存空間。JSON用於少量階層式audit metadata；不是把原始旅次轉成JSON，也不改變未來分析中間表優先Parquet的原則。

在repository根目錄執行PowerShell：

```powershell
$sourceIndex = (Get-ChildItem references -Filter '*V5*.csv').FullName
$rawZip = 'data/raw/202311_YouBike2.0票證刷卡資料.zip'
python src/audit_youbike.py --index $sourceIndex --month 2023-11 --raw $rawZip --output data/interim/audit-2023-11.json
python -B -m unittest discover -s tests -v
```

新checkout尚無ZIP時可在同一audit命令加`--download`，只下載指定月份；目標存在會拒絕覆寫。若要重新檢查索引所有連結，加`--probe-links data/interim/index-link-checks.json`，只做HEAD。重跑不加此參數則完全使用本機檔案。輸出路徑不可與來源路徑相同。

可重現的固定摘要保存在`notes/audit-evidence.json`；網路回應時間等可變資訊另存`notes/source-receipt.json`，不拿HEAD時間戳做重跑一致性比較。重新下載的原始檔若hash不同，應記為來源版本差異，不覆寫舊快照硬湊結果。
